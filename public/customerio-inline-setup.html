Research scope and experience decisions

Included delight opportunities

  1. Recognize compatible existing work before requesting credentials.
  2. Extract JSON and connection details into editable fields.
  3. Suggest a starting point grounded in a visible sample schema.
  4. Show the resulting person, event, or spreadsheet row.
  5. Explain empty previews and offer a concrete recovery.
  6. Keep valid fields when a check fails.
  7. Save a credential-free draft and resume at the current step.
  8. Summarize changes, support undo, and invalidate older previews.
  9. Separate connection, preview, activation, and first-outcome evidence.

What this prototype tests

Website SDK, PostgreSQL, Salesforce source, and Google Sheets destination paths share one summary, inline conversation, and current tool. Guided responses run locally. Account names, database rows, authorization, and completion evidence are simulated.

The separate SDK test website exercised real ingestion into the test workspace. A prototype completion here is not a live connection or a real import.

Uses Pluma's documented form, panel, text-field, and inline Agent patterns with selected light-theme tokens. This static exploration does not load production Pluma components.

Next validation questions

Can someone switch between conversation and controls without repeating information? Which choices need clarification? Is the next action apparent? Does a success state make clear what was actually verified?
